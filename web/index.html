使用前请确认
  • 纯本地、个人自用，不分发、不代签；所有请求保持低频串行，随时可「一键停用自动化」。
  • 写操作默认关闭：这是安全默认值，关闭时点签到不会提交任何请求。需要签到请先到「设置」打开「允许写操作」；当日已成功或服务端判定已签的账号会被幂等跳过，不会重复提交。
  • 周本次数已启用（第四项）：roleHome 按角色条件性下发 weekcopiesremainCnt（本周剩余次数，0 = 已打完）。有字段显示真实 x/3；没有字段（存档未同步，比如刚打完还在游戏里）显示「—」并标「未同步」，绝不把官方 H5 的 3/3 兜底常量伪装成实时数据。分母 3 是前端常量，本项不计入提醒。
  • 抽卡统计已常驻：官方 gacha 只读接口，按卡池列出每个角色/弧盘的获取花费抽数与逐次出货累计抽数；中文名来自官方角色字典，未覆盖的只显示 ID（可点击自定义别名）。出货时间只认 timeStamp，不写任何官方数据。
  • 账号显示可自定义：点卡片标题旁的 ✎ 可改标题 / 副标题显示内容，随时「还原原显示」；只作用于本机浏览器显示层，不写数据库、不改官方数据。账号卡片末尾的「抽卡统计」只查看本地已保存的快照，不刷新、不入队、不发任何官方请求。
  • 签到详情 / 补签 / 呗果：卡片上的「签到详情」只读拉取呗果余额、补签次数与本月累计签到奖励表（环石已加粗，勾选 = 已签，高亮 = 今天），不发任何写请求；「补签」会真正提交官方 resign，每次消耗 200 呗果、每月上限 3 次，且官方要求当日已签到后才能补，补的是「当日签到后下一日」的奖励。

使用说明 / 数据口径 / 合规边界

怎么开始：点「导入现有 TOKEN.txt」可免短信复用已验证的 accessToken；或点「手机号 + 验证码授权」新增账号。授权后点账号卡片上的「刷新数据」，即可看到四项数值。

前三项数据口径：本性像素、都市活力取 roleHome 接口的当前值与上限（一律以接口为准，不写死 240）；活跃度取 dayvalue，分母 100 是官方 H5 前端常量，界面会标「分母常量」。上限缺失时才用官方兜底值推算，并标「推算」。

第四项「周本次数」口径：取 weekcopiesremainCnt（本周剩余次数，0 表示本周已打完），分母 3 是官方 H5 前端常量。该字段是存档字段：本周进过游戏、存档写入并退出后才会出现在角色数据里（实测同一角色退出前后 22 键 / 23 键）。有字段时显示真实 x/3 并标「接口真值」；没有字段时显示「—」并标「未同步」，绝不把官方自己的 3/3 兜底常量当成实时数据。本项只作展示，不计入任何提醒；可在设置里关闭显示。鼠标悬停在标签上可看口径说明。

抽卡统计口径：官方 gacha 返回的是「聚合统计 + 稀有出货明细」，不是逐抽流水。卡池层 drawCount 是该池累计抽数；明细层 rareCount（与卡池层同名字段语义完全不同）是本次出货距上次出货所用抽数，也就是拿到这个角色花了多少抽。看板按物品汇总「合计花费抽数 / 平均 / 最非一次」，并在逐次明细里给出按时间前缀和计算的「累计抽数」与距保底进度。出货时间只取 timeStamp，因为 time 字段实测恒为抓取当天。若明细抽数之和小于卡池累计抽数（官方记录疑有滚动保留期），界面会明确标注累计只覆盖现存明细，不会把残缺数据当成开服至今总账。luckyType 原样展示，含义未定案。

抽卡物品名称：charid 只有 ID。中文名来自官方 characters 字典接口（角色数字 ID、fork_ 弧盘），日常 roleHome 刷新也会顺手维护，全程不猜名称。字典未覆盖的物品只显示 ID 并标「未下发名称」，点击名称可设置本地别名（只影响显示，优先级高于官方名称，留空即恢复）。

账号显示自定义：点账号卡片标题旁的 ✎ 打开「自定义显示」：标题可切换为原显示（备注）/ 角色名 / 手机号掩码 / 自定义文字，副标题可整段替换或按字段勾选显示（手机号掩码、角色名、凭证类型）。设置只存在本机浏览器 localStorage，不写入 SQLite、不改官方账号、不影响签到 / 刷新 / 抽卡数据；「还原此账号」或「全部还原」立即恢复服务端原始字段。换浏览器或清理浏览器数据后会回到原显示。

账号卡片上的「抽卡统计」：只把下方抽卡区块筛选成该账号的本地已保存快照并滚动过去，不会入队、不会刷新、不会请求官方 gacha；区块顶部会标出数据抓取时间和「仅查看本地快照」。想更新数据请显式点「抓取全部账号」或该账号区块里的「抓取此账号」。点「显示全部账号」退出单账号筛选。

备注：点「备注」会弹出输入框，把填写的文字经 /api/account/update 写进本地 SQLite 的 accounts.remark 字段（最长 30 字）。它只是本地标签，作为账号卡片与抽卡区块的默认标题，不会同步到官方、不会改角色名 / 手机号 / 凭证，也不影响签到与数据刷新；留空保存会清掉标签，标题回落到「未命名账号」。它是写数据库的操作，与上面只存浏览器的「自定义显示」互不影响。

签到详情 / 补签 / 呗果：账号卡片上的「签到详情」做一次只读查询（signin/state、resign_info、sign/rewards、sign/reward_records），把呗果余额、补签消耗 / 剩余次数、本月累计签到奖励表（30 天）和最近到账流水缓存到本地 signin_info 表；看板随 /api/state 一起下发，不需要每次额外请求。奖励表里环石（高级货币）会加粗高亮，已签的格子打勾、今天的格子描边。点「补签」会真正提交官方 POST /apihub/awapi/resign（form roleId + gameId），因此同样受「允许写操作」开关保护，提交前会二次确认并显示消耗与剩余次数。官方前置条件：必须当日已签到；每次消耗 200 呗果；每账号每月 3 次、每月 1 日 00:00 重置；补签自动补「当日签到后下一日」的奖励。呗果不足、次数用完、今日未签都会在前端按钮置灰并在后端再校验一次，不会白提交请求。补签奖励与签到一样经游戏内邮箱发放。

签到模式（2026-11-08 更正）：默认执行异环游戏内每日签到（gameId=1289）：先只读 signin/state 判断今日是否已签，未签才 POST /apihub/awapi/sign（form: roleId + gameId），随后用 sign/reward_records 核对实际到账奖励，显示为账号卡片上的「今日已签 · +道具×数量」。社区版区签到（/apihub/api/signin）只发社区经验/金币，不是游戏奖励，仅保留为可选模式；communityId 已从 1（幻塔）更正为 2（异环）。

为什么奖励会「签了但邮箱没有」（2026-11-08 定案）：纯签到只把记录写在社区侧，不会把道具推进游戏邮箱。真正让奖励投进邮箱的是 POST /usercenter/api/autoBindGameRole（form: gameId + roleId）——这正是塔吉多 App 登录后自动执行的一步，所以才有「登录一次塔吉多邮箱才有东西」的现象。本工具现在会在签到成功后、以及今日已签两个分支都自动调一次该接口；已签但邮箱仍为空时，签到详情弹窗里点「补投递」手动触发。注意它不改签到状态、不消耗呗果、不重复发奖；触发后仍需完全退出游戏再重进，邮箱列表才会刷新。

签到幂等：以「账号 + 日期 + gameId=1289」为唯一键，当日已成功直接跳过、根本不发请求；再叠加服务端 signin/state.todaySign=true 与「已签到 / 签到过 / 重复签到」文案判据。旧社区记录（community_id=1，其实是幻塔）不参与游戏签到判据，不会被误显示成「今日已签」。

凭证安全：accessToken 用 Windows 系统 DPAPI 加密（密文绑定当前 Windows 用户），SQLite 只存引用与版本戳；验证码只在内存，手机号只存掩码；日志自动脱敏。V2 协议不签发 refreshToken，过期需重新收一次短信，不会静默重试。

范围：异环游戏内每日签到（含手动补签）、四项实时信息与抽卡统计；社区版区签到仅作可选兼容。不含幻塔任何功能、任务中心、兑换中心、角色卡片等。补签必须手动点、手动确认，自动化不会触发任何补签。抽卡抓取与签到详情都是只读 GET，与刷新/签到共用同一条串行限速队列，不因账号多而并发打满请求。

风险提示：第三方客户端存在协议变更与账号风险。若接口报「疑似协议改版」，请在 adapters/1.2.8.json 更新端点/签名常量后重启；如不再使用，删除 data/ 目录即可彻底清除本地凭证。
